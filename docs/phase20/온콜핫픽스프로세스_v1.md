# Phase 20 온콜·핫픽스 프로세스 v1.0

## 온콜 체계

- 1차 담당: API/DB 운영자
- 2차 담당: 도메인/세무조정 담당자
- 대응 시간: 24/7, Critical 즉시 대응

## 장애 등급

| 등급 | 기준 | 목표 대응 |
|------|------|-----------|
| Critical | 신고 불가, 데이터 손상, 테넌트 격리 실패 | 즉시 대응, 핫픽스 |
| High | 주요 업무 중단, 대량 job 실패 | 4시간 내 조치 |
| Medium | 우회 가능한 기능 오류 | 다음 패치 |
| Low | 문구/표시/편의성 | 백로그 |

## 핫픽스 절차

1. 장애 접수 및 영향 범위 확인
2. 재현 케이스와 로그 확보
3. hotfix 브랜치 생성
4. 수정 후 `node --check`, `cargo fmt --check`, `cargo test --all --all-targets`, clippy 실행
5. Docker API 이미지 빌드 및 staging smoke test
6. 운영 배포 및 `/ready` 확인
7. 사후 보고서 작성
